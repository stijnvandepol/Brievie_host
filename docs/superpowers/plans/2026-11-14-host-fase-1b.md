# Host Eerste lijn (fase 1b) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A scanned letter that the iPhone uploads (page images + on-device OCR text) is stored encrypted, processed by a background worker (BSN masking, AI extraction through an OpenAI-compatible API or no AI, deterministic validation) and offered for review; after the user confirms, it has a task with a deadline whose source is visible.

**Architecture:** The app uploads one `multipart/form-data` request per document (atomic, idempotent on a client-chosen id). The `documents` app stores the document, its pages (AES-GCM, key per workspace) and the masked OCR text, and defers a Procrastinate job in the same transaction. The `brievie-worker` container (same image) runs `apps.pipeline`: a row of small steps (mask → extract → validate → store proposals), each with its own input and output type, idempotent, run inside `workspace_context`. Proposals are `Extraction` rows; `confirmDocument` turns confirmed values into document fields and `Task` rows.

**Tech Stack:** As in 1a (Python 3.13, Django 6.1, Django Ninja, psycopg 3, PostgreSQL 18, pytest), plus Procrastinate (job queue in PostgreSQL), `cryptography` (AES-GCM), `httpx` (calls to the AI API).

**Spec:** `docs/SPEC.md` sections 7, 10, 11, 12, 14, 16 (step 1b and the acceptance criteria), 18, 19. Previous plan: `docs/superpowers/plans/2026-11-13-host-fundament.md`. iOS counterpart: `../Brievie_ios/docs/superpowers/plans/2026-11-14-ios-fase-1b.md`.

## Decisions taken with the owner (2026-11-14), to record in `docs/DECISIONS.md`

- **No heavy work on the server.** OCR happens on the iPhone (Apple Vision); in 1b the app is the only intake, so the server runs no OCR. OCRmyPDF/Tesseract arrive with web upload and the watch folder (1d). This deviates from the 1b row in spec section 16.
- **AI through an API by default.** Modes `off`, `external`, `local`; `external` and `local` are the same OpenAI-compatible provider with a different URL. Default provider for `external`: Mistral (`https://api.mistral.ai/v1`, EU company, structured JSON output). `local` (Ollama) stays possible for owners with the hardware but is not tested on real hardware in 1b. New workspaces start with `off`.
- **No web screens in 1b.** The result is reviewed in the app. AI settings are set with a management command; the web settings screen comes with the wizard (1d).

## Global Constraints

- Everything in the Global Constraints of the 1a plan still holds (English code, Dutch B1 text through `gettext`, UUID `id` + `created_at` + `updated_at`, `mypy --strict`, `ruff`, `Decimal` money, aware datetimes, `/api/v1` additive only, camelCase `operation_id`, `{"code", "message"}` errors, thin endpoints, no secrets/document content/BSN in logs, no Redis/Celery/Node container).
- Every new workspace table subclasses `WorkspaceModel`; its first migration ends with `enable_rls(<table>)` (enabled **and forced**). `tests/test_rls_coverage.py` must pass unchanged.
- Every background job takes `workspace_id` and runs inside `workspace_context(workspace_id)`. Job arguments are ids only, never text.
- No plaintext document bytes on disk: pages are encrypted before they touch storage; uploads are parsed in memory, never via Django's temporary-file upload handler.
- BSNs are masked before any text is written to the database, a log line, or an AI request.
- Every AI value carries its source quote and a confidence; a value whose quote is not literally in the text gets confidence 0 (spec 10.6). Below 0.85 on a deadline or amount: `needs_attention` (spec 10, "Drempel").
- AI proposes, the user confirms: no `Task` exists until `confirmDocument`.
- Every external call (the AI API) goes through an interface with a fake for tests, a timeout and a bounded number of retries.
- No new dependency without a line in `docs/DECISIONS.md` (version, reason, alternative dropped).
- Work on branch `feat/fase-1b`. Conventional commits. Do not push.

## Review Focus

1. The same document is uploaded twice (the app retries after a lost response): one document, the second answer is 200 with the same body; a different upload under the same `client_id` is 409 and changes nothing. → Task 6.
2. The worker is killed or the AI API times out halfway: the job retries, the document ends in `needs_review` with exactly one set of proposals, or in `failed` with a code; never stuck in `processing`, never duplicate proposals. → Tasks 5 and 9.
3. The model returns a date, amount or sender that is not in the letter (hallucination), or malformed JSON: confidence 0 / `failed` with `ai_invalid_output`, never a silently trusted value. → Tasks 7 and 9.
4. A letter contains a BSN with dots or spaces (`123.456.782`, `1234 56 782`): it is masked in the stored text, in the AI request and in logs; a 9-digit number that fails the elfproef (a phone or invoice number) is left alone. → Tasks 2 and 9.
5. A request body without `Content-Length` (chunked) or larger than the limit: 411 `length_required` / 413 `payload_too_large` in the API error shape, nothing stored, no 500 and no 502. → Tasks 1 and 6.

### Task 1: Contract fixes: nullable fields and bodies without Content-Length

The iOS generator (swift-openapi-generator 1.12.2) skips properties written as `anyOf: [X, {"type": "null"}]`, so `FolderOut.parent_id` and `DeviceOut.last_seen_at` never reach the app. And a chunked request body (no `Content-Length`) reaches Django as an empty body, so the API answers 415 or 422 instead of saying what is wrong.

**Files:**
- Create: `backend/apps/common/openapi.py`
- Modify: `backend/apps/common/management/commands/export_openapi.py` (`render_schema` post-processes), `backend/apps/common/errors.py` (new middleware + 411 body), `backend/brievie/settings.py` (`MIDDLEWARE`), `docs/api/openapi.json` (regenerated), `web/src/api/schema.d.ts` (regenerated), `docs/DECISIONS.md`
- Test: `backend/tests/test_openapi_contract.py`, `backend/tests/test_api_content_length.py`

**Interfaces:**
- Produces: `apps.common.openapi.normalize_nullable(schema: dict[str, object]) -> dict[str, object]`: returns a copy where every `anyOf` of exactly one primitive schema (`type` is `string`, `integer`, `number` or `boolean`, any `format`) plus `{"type": "null"}` becomes that schema with `type: [<type>, "null"]` (other keys such as `format`, `title`, `default` kept). Any other `anyOf` containing `null` (a nullable `$ref` or object) raises `ValueError` naming the JSON pointer: such a field must be designed differently (omit it, or use an empty list), because it would not survive the generator either.
- Produces: `apps.common.errors.ApiContentLengthMiddleware`: an `/api/` request with `Transfer-Encoding` and no `Content-Length` gets 411 `length_required` ("Dit verzoek mist een lengte. Probeer het opnieuw.") before any view runs. Placed before `ApiJsonBodyMiddleware`. `_http_error_body` gains `411`.
- Contract rule (test): the exported schema contains no `anyOf` anywhere.

### Task 2: BSN masking

**Files:**
- Create: `backend/apps/common/privacy.py`
- Modify: `backend/brievie/settings.py` (`LOGGING`: the filter on every handler)
- Test: `backend/tests/test_common_privacy.py`

**Interfaces:**
- Produces: `find_bsns(text: str) -> list[tuple[int, int]]`: spans of candidate BSNs: 9 digits, optionally grouped with single dots or single spaces as `ddd.ddd.ddd`, `ddd ddd ddd`, `dddd dd ddd` or `dd.dd.dd.ddd`, not adjacent to another digit or letter, that pass the elfproef (`9*d1 + 8*d2 + … + 2*d8 - 1*d9` divisible by 11, not all zeros). - Produces: `BsnMaskingFilter(logging.Filter)`: masks `record.msg` and string `record.args` (formats the message first, then masks, then clears `args`).

Pure functions; no database, no network.

**Files:**
- Create: `backend/apps/pipeline/schema.py`, `backend/apps/pipeline/validation.py`

**Interfaces:**
- Produces: `schema.ExtractionPayload` (Pydantic, `extra="forbid"`): the 1b subset of the spec 10 schema with the Dutch field names as aliases: `afzender {naam, bron, zekerheid}`, `documenttype`, `dagtekening {waarde, bron, zekerheid}`, `samenvatting_b1`, `acties[] {type, omschrijving, deadline {waarde|null, bron|null, zekerheid}}`, `factuur {nummer|null, vervaldatum|null, bedrag_incl|null, bron, zekerheid} | null`. Snapshot-tested (`tests/fixtures/extraction_schema.json`).
- Produces: `validation.ValidatedValue` (frozen dataclass): `field: str`, `group: int`, `value: str`, `quote: str`, `confidence: Decimal`.
- Produces: `validation.validate(payload: ExtractionPayload, text: str, *, today: date) -> list[ValidatedValue]`. Rules, each a small named function:
  - `quote_in_text(quote, text)`: case-insensitive, whitespace collapsed on both sides; false → confidence 0.
  - the value must be found in its quote: dates parsed from the quote in Dutch forms (`14-11-2026`, `14 november 2026`, `14 nov. 2026`) must equal the value; an amount in the quote (`€ 1.234,56`, `1234.56`, `EUR 12,-`) must equal the value as `Decimal`; otherwise confidence 0.
  - plausibility: `letter_date` within [today − 10 years, today + 30 days]; deadlines within [letter_date or today − 1 year, today + 5 years]; else confidence 0.
  - unparsable amount or date → the value is dropped (never stored), not "confidence 0 with garbage".
  - confidence from the model is clamped to [0, 1] and never raised by validation.
  - Dutch enum values map to the English codes of Task 4 (`factuur` → `invoice`, `betalen` → `pay`, …); unknown values → `other`.
  - `summary` is exempt from the quote rule (generated text) and keeps the model's confidence.
- Produces: `validation.NEEDS_ATTENTION_BELOW = Decimal("0.85")` and `needs_attention(field: str, confidence: Decimal) -> bool` (true only for `action_deadline`, `invoice_due_date`, `invoice_amount_incl` below the threshold).
