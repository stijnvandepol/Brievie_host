# Trash for letters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A trash for letters: soft delete, restore within 30 days, then a final purge of rows and sealed page files, with rights, history, audit rows and a web page.

**Architecture:** `Document.trashed_at` (+ `trashed_by`, `purge_started_at`). The seam `visible_documents` excludes trashed letters and a sibling `trashed_documents` lists them; off-seam paths filter `LIVE`. `apps/documents/trash.py` holds trash, restore, purge-now and empty; `apps/documents/purge.py` the job body (mark, remove files, delete rows, under `backup_lock`); `apps/documents/page_files.py` is the only code that removes a letter's sealed files and refuses on its own.

**Tech Stack:** Django 6.1, Django Ninja, PostgreSQL 18 (forced RLS), Procrastinate, React 19 + TanStack Query/Router + React Aria + Lingui, Vitest + MSW.

**Spec:** `docs/superpowers/specs/2026-11-20-trash-design.md` (read it first; its Rulings bind). Assignment with the binding safety rules: `.superpowers/sdd/2026-11-20-trash/assignment.md`.

**Start condition:** building starts only after the first merge point of `feat/wie-ziet-wat` (PR #26) is in `main`: it changes the same visibility code in `apps/documents` (`visibility.py`, the reads behind it). The builder first rebases `feat/trash` onto that `main` and puts `trashed_documents` next to whatever `visible_documents` has become (the trash filter stays on top of the rights model, never instead of it).

## Global Constraints

- `CLAUDE.md` "Rules in short" applies in full. In particular: API additive under `/api/v1`; every endpoint typed with an explicit camelCase `operation_id`; new fields on existing schemas have defaults; nullable only primitives; no `anyOf`; errors via `ApiError` with a Dutch B1 message; thin endpoints calling one service function; every mutating service in `transaction.atomic`.
- Only `apps.documents.organise` writes a letter's history; only `apps.audit.services.record()` writes audit rows, with codes from the closed list and ids only for a document.
- `TRASH_RETENTION = timedelta(days=30)`; purge cron `"41 * * * *"`; batch `limit=100`; trash list cap 500.
- Audit codes exact: `document_trashed` (`reason`: `user`), `document_restored` (none), `document_purged` (`reason`: `admin`, `emptied`, `expired`).
- Error codes exact: 404 `document_in_trash`, 409 `document_trashed`, 409 `document_retained` (only when the retention hook refuses; never today); everything else reuses `document_not_found`, `task_not_found`, `forbidden`.
- Deleting code (binding, verbatim from the assignment): "Code die bestanden of mappen verwijdert, verplaatst of overschrijft wordt nooit uitgevoerd op de Mac zelf buiten een tijdelijke map van de test (tmp_path) of binnen een container. Geen absolute paden in tests voor zulke code, behalve onder die tijdelijke map." A refusal test calls the judge, never `remove_document_files` with a path outside `tmp_path`. The refusal lives inside the removal function.
- `DocumentStorage.delete` is not used by trash or purge.
- No document content (sender, summary, text), no paths in logs: ids and exception type names only.
- `mypy --strict`, `ruff check`, `ruff format --check`, `pnpm lint`, `pnpm typecheck` clean. No `Any`, no bare `except`.
- Web text Dutch B1 through Lingui `t`; run `pnpm extract`. "Te doen" and "Alle post" keep their names.
- Never touch Docker; never print `deploy/.env`; no push, no tags.
- Conventional commits, each ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Run the test files you touch plus the ones your task names (`cd backend && uv run pytest tests/<file>`); the controller runs the full suite.

## Review Focus

1. A trashed letter reached through a path that is not on the seam (a lock query, a job, a count, an export read): expected 404 / skipped / not counted. Pinned by the parametrised test in Task 2 and the reads test in Task 1.
2. Restore racing the purge (restore after `purge_started_at` is set): expected 404, files and rows go. Pinned in Task 5 (`test_restore_after_mark_is_refused`).
3. A storage root setting that points at a home directory, `/`, the back-up mount or a symlink: expected refusal before anything is listed. Pinned in Task 4 through `judge_storage_root`.
4. A crash between file removal and row deletion: expected the row stays marked, hidden, and the next run finishes it. Pinned in Task 5 (`test_purge_resumes_after_files_removed`).
5. Emptying the trash while a member trashes another letter: expected only letters with `trashed_at <= up_to` go. Pinned in Task 5 (`test_empty_trash_respects_up_to`).
